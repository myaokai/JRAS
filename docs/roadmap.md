# 実装ロードマップ

[requirements.md](requirements.md) の要件を、[wireframes.md](wireframes.md) の画面構成と [infrastructure.md](infrastructure.md) のインフラ設計で実装していく順序。

## 方針

- **試験日から逆算する**: 短答式（例年5月）までに短答の強化を、論文式（例年8月）までに論文対応を使える状態にする。目標時期は2026年10月時点の見込み。
- **学習記録を最初に守る**: データ形式や画面を大きく変える前に、書き出し・読み込み（NFR-04）を入れる。今の学習記録はブラウザ内（localStorage の `problemRecord` / `habitRecord` 等）にしかない。
- **端末側を正とし、サーバーは同期だけ**: 解答・閲覧は端末内（IndexedDB・Service Worker）で完結させ、D1 には解答ログを後から送る。オフラインでも使え、スマホとPCで記録を共有できる。
- **データ作りと実装を分ける**: 解説・論点・カードなどのデータ作成は時間がかかるので、仕組みを先に作り、データは後から少しずつ足せるようにする（追加項目はすべて省略可、NFR-05）。
- **各段階で使える状態を保つ**: 段階ごとにデプロイし、PWA として毎日使いながら進める。

| 1 | データの不備を直す | DR-01, DR-02 | 08, 09, 03 | S〜M | 2026年11月 |
| 2 | 短答式の強化・記録の同期 | FR-14, FR-11, FR-12, FR-34（試験日）, NFR-04（同期） | 01, 02, 03, 04, 05, 06, 07 | L | 2027年2月 |

## 段階0　基盤（まず最初に）

ワイヤーの画面構成（下部タブ＋出題中は下部固定ボタン）に作り替えるための土台。

| # | タスク | 内容 | 完了条件 |
|---|---|---|---|
| 0-1 | 学習データの書き出し・読み込み | localStorage の全キーを1つのJSONにまとめて書き出し、読み込み時は上書きの確認を出す。データにバージョン番号を持たせる | 書き出したファイルを別のブラウザで読み込むと、記録・連続日数・履歴が戻る |
| 0-2 | 記録を解答ログ形式にする | 端末側の保存先を IndexedDB に移し、解答ログ（問題ID・モード・結果・日時）で記録する。復習状態はログから計算する。問題IDに科目の接頭辞を付ける規則を決める（既存IDはそのまま）。既存の記録は snapshot として移す（[infrastructure.md](infrastructure.md) の「既存データの移行」） | 既存の記録を失わずに新形式で読める。ログから計算した復習状態と移行処理にテストがある |
| 0-3 | 画面遷移の仕組み | 下部タブ（ホーム／学習／教科書／記録／設定）と画面の階層を作る。URLのハッシュで画面を表し、スマホの「戻る」操作で前の画面に戻れるようにする | ワイヤー01・02・08・14・15の枠（中身は仮）にタブで移動でき、戻る操作が効く |
| 0-4 | 共通部品 | 画面の枠、ヘッダー、下部固定ボタン、チップ、カード、進捗バーをワイヤーに合わせて作る | 既存の穴埋め・過去問・教科書が新しい枠の中で今までどおり動く |
| 0-5 | テストの整備 | Vitest を入れ、`leitner.ts`・`habit.ts`・保存形式の移行に単体テストを書く。`verify_checks.cjs` を新しい画面遷移に合わせて直す | `npm test` と `verify_checks.cjs` がどちらも通る |
| 0-6 | インフラの土台 | 今のデプロイ方法（Git 連携か `wrangler deploy` か）を確認する。Worker に `/api/*`・`/audio/*` の振り分けを足し（`run_worker_first` にも追加）、`/api/me` だけを仮で実装する。`wrangler dev` でローカルの D1・R2 を使えるようにし、開発用ユーザー `DEV_USER` を設定する | ローカルとデプロイ先の両方で `/api/me` が応答し、静的ファイルの配信と PWA の更新が今までどおり動く |
| 0-7 | 認証の実機検証 | Cloudflare Access で**アプリ全体**を保護し（ログインは Cloudflare アカウント）、Worker で JWT を検証する。iPhone のホーム画面版でログインしてアプリに戻れるか確かめる | **完了**（2026-10-12）。iPhone でログインしてアプリに戻れたため Access に決定。結果は [infrastructure.md](infrastructure.md) |

依存関係：0-1 → 0-2（記録を守ってから形式を変える）、0-3 → 0-4、0-6 → 0-7。0-6・0-7 は画面側の作業と並行して進められる。
